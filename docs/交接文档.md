### 重跑环境

用 Steam 版 1.0.30000、BepInEx 5.4.23.4 和可从 `Abyss_12` 椅子进场的第二槽副本。装备以本局遥测的 `WANDER_SAVE_GEAR` 与 `WANDER_EXTRA_GEAR` 为准。

旧版仓库根目录的 `Silksong-TAS.ps1 -PrepareOnly` 可准备隔离游戏，参数为 `-Stage`、`-SteamGame`、`-Slot2`，必要时指定 `-ModProfile`。准备后，在仓库根目录执行下面的编译步骤。请沿用准备隔离副本时的 `$stage`。

```powershell
$route = Join-Path $PWD 'replays\prefillholdlift-0002'
$game = Join-Path $stage 'Game'
$managed = Join-Path $game 'Hollow Knight Silksong_Data\Managed'
$core = Join-Path $game 'BepInEx\core'
$csc = Join-Path $env:WINDIR 'Microsoft.NET\Framework64\v4.0.30319\csc.exe'
$refs = @("$core\BepInEx.dll", "$core\0Harmony.dll")
$refs += @(
  'Assembly-CSharp.dll', 'UnityEngine.CoreModule.dll', 'UnityEngine.dll',
  'UnityEngine.Physics2DModule.dll', 'PlayMaker.dll', 'netstandard.dll',
  'TeamCherry.SharedUtils.dll', 'Unity.Addressables.dll', 'Unity.ResourceManager.dll',
  'UnityEngine.ImageConversionModule.dll', 'UnityEngine.AudioModule.dll'
) | ForEach-Object { Join-Path $managed $_ }
& $csc /nologo /target:library "/out:$game\BepInEx\plugins\SilkPractice.dll" ($refs | ForEach-Object { "/r:$_" }) "$route\SilkPracticePrefillHoldLift.cs"
if ($LASTEXITCODE -ne 0) { throw 'TAS controller build failed' }
Copy-Item -LiteralPath "$route\openfive-inputs.tsv","$route\return295-choices.tsv" -Destination $stage
$env:SILK_PRACTICE_DIR = $stage
$env:SILK_PRACTICE_CAPTURE_DIR = $stage
Start-Process -FilePath "$game\Hollow Knight Silksong.exe" -WorkingDirectory $game -WindowStyle Hidden -ArgumentList '-screen-width','960','-screen-height','540','-screen-fullscreen','0'
```

从 `command.txt` 逐条取命令，通过 `.\Silksong-TAS.ps1 -Stage $stage -Command $command` 发送。每条处理完再发送下一条。`load` 后等 `SCENE Abyss_12`，再等待约 2.6 秒。两条 `step` 各自等待 `STOP`。最终以 `PREFILL_READY`、`PREFILL_ENTRY`、`START_LOAD` 与 `RACE_END` 验证，结束后发送 `quit`。录像曾按要求清除，重新运行可采集帧。

## 2026-11-24　完整丝槽满丝路线

新口径使用第二槽隔离副本，要求无茧、完整丝槽、开战 17/17 丝、全程后台静音。战吼结束首次可操作时，通过原生丝量接口在练习副本内补满并验证血量为八格。该轮最快为 **46.967 秒（2818 帧）无伤**，末帧蕾丝 HP -96。

拾茧对照在 3 丝基础上增加 9 丝，到 12/17。满丝规则明确后，从完好无茧的第二槽启用满丝开局。全程静音由控制器的每帧音量约束与首帧记录共同核对。

`leftstage-0001` 在 564 帧进入中场，2534 帧回场时蕾丝为 832 HP。火刀在转阶段空档预备，回场后在 2559、2591、2642、2678、2711、2752、2823、2854 帧命中，每刀 105，终点为第 2854 帧。`frontchoice-0001` 把首次随机选项改为闪避后，前五次火刀暴击在第 166 帧已经完成，215 帧受击，未计入无伤成绩。保留这一开局的关键是连斩第二拍提早离开攻击线。尾段逐帧核对发现，丝刃输入可能下一帧就被追击覆盖，发出按键并不等于扣丝。新实验保留施法输入并以实际扣丝和原生扣血判断收益。该局之后受击，未计入成绩。`wavecoast-0002` 在 512 帧进入中场，2479 帧回场，剩 865 HP。第 2779 帧仍剩 13 HP，第 2818 帧在第四阶段早期用第九刀结算。相对 47.567 秒局，回场早 55 帧，尾段多用 19 帧，合计快 36 帧。读取本机游戏输入逻辑后确认，快键走原生 CanThrowTool 门槛，刀的回收期间即使 CanCast 为真也可能收不到快键。后续测试按真实工具门槛选择施法帧。另两局在进入中场后贴在蕾丝身边受击，因此在无敌中场开始时转向墙边，保留后续测试的无伤资格。

满丝改变伤害与停顿，原来零丝路线的输入不能按旧帧号直接粘贴。以 `outcomes.tsv` 的原生结算、逐帧八格、蕾丝负血和满丝起始为准。`profiles.txt` 记录每次试跑的准备帧数、控制器和命令。带 `capreplay` 的构建读取同目录的 `cap-inputs.tsv` 与 `cap-choice.tsv`，其余参考表在上层或同级 Retiming。

`reserve-0003` 是限定火刀和酒只用空档后的最低剩余 HP 样本，掉血前已经叠满专注。上表时间均为首次失血帧。从改回指定双红槽起，日志共记录 71 局结束的整场尝试，均在第一次失血停止。两次因配装标签触发了十字绣而被开局校验中止，没有纳入统计。

## 接手时优先修的地方

1. **二阶段追击的残留虚空柱。当时蕾丝在空中鞭状态，同帧实际命中来自 `Lost_Lace_tendril_set`。处理鞭和落刺时还要保留虚空柱的安全走位，尤其是已有侧向跳或冲刺预输入时。以 `BOX_CONTACT` 与同帧 `RHP` 核对。
2. **钩爪与余弹。最新源已让两个追击分支共用留丝条件，排除虚空弹及喷吐残留时间。虚空弹预判用实际刚体速度和重力。用 `NATIVE_BOSS_HIT` 统计伤害来源，用 `NATIVE_SPEND` 查 1 丝钩爪与 3 丝施法。
3. **冲刺与二段跳。** 冲刺结束可能直接接快斩。第二次跳跃需要先松开跳键至少一帧，见 `KEY_REPRESS`。横向跨过蕾丝前要有足够高度，留意第三次突进末尾的快斩。圆斩先向外撤，靠真墙再选向场内的路线。
4. **两道虚空浪。最新控制器读取原生浪体位置与速度，临近时起跳并保留二段跳。第二道浪和后续阶段尚无无伤通过实测。先验证整场，再以 10 秒伤害和阶段用时筛选压时间。

## 从长期目录继续

源代码、启动器、编码器和快照都在长期目录下。清空临时目录后，可以用长存入口重建。当前交接只核对了文件和入口的 PowerShell 语法，没有重新启动游戏。

```powershell
$tool = ''
& "$tool\Race\Run-LostLaceMarathon.ps1"
```

- `Race\SilkPracticeMarathon.cs` 是最后一次实测的控制器。正式 Steam 游戏和存档目录无需为后续练习改动。主启动器的 `-Marathon` 可单独创建该控制器的隔离实例。单次仅跑一个实例。临时并行副本未进入试跑，不作为交接依赖。
- 起始快照为 `Checkpoints\LostLace-SecondSlot-CocoonRecovered-Practice.dat`。脚本检查红槽、法术、无茧、零丝和静音条件，逐局从该快照冷启动。随机分支会受进场执行影响。同一输入记录和种子跨次运行仍可能分歧。
- 长期证据在 `2026-11-23\MarathonEvidence`，包括停止时的完整日志、14 局初筛 CSV 和关键样本的逐帧数据与输入。用对局名搜索 `RACE_ARM`、`RACE_START`、`RHP`、`BOX_CONTACT`、`RACE_END`。
- 后续出现合格的首杀，脚本会保存原始记录并生成 ，同时保存逐帧计时和原始输入。录像从战吼前保留至经核验的负血帧。完整无伤击杀时间每次刷新时另存该局录像。
